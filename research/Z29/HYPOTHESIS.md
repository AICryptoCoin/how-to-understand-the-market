## 1. Контроль честного прогона (до всех утечек)

До запуска каких-либо утечек исходник `Z28/run.py` исполняется в памяти без изменений с включённым аудитом информационного множества на обоих маршрутах:

**Критерий честного прогона:**
Поштучные разности штрафов `delta_pp = crps_baseline_pp - crps_price_pp` сравниваются со значениями `routes.<route>.per_date[].delta_pp` из опубликованного `research/Z28/result.json`.

* Если максимум расхождения превышает порог из-за обновления внешних рядов поставщиками (Yahoo поправил цены, Шиллер обновил файл `ie_data.xls`), факт сдвига данных фиксируется с паспортом данных рядом с паспортом `Z28`, и **все пять утечек считаются на тех же текущих данных**, что и честный прогон (сравнение ведётся на одних и тех же данных).

## 2. Пять утечек на приборе Z28 (закрытый список)

Каждая утечка представляет собой строковую замену в исходнике `research/Z28/run.py` перед исполнением в памяти.

### L1. Ансамбль видит на месяц вперёд (граница окна)
* **Целевая строка в `Z28/run.py`** (строки 642–644):
```python
        scenario_points = tuple(
            annual[HORIZON:i + 1]
        )  # MUTATE_FUTURE_BOUNDARY
```
* **Замена:**
```python
        scenario_points = tuple(
            annual[HORIZON:i + 2]
        )  # MUTATE_FUTURE_BOUNDARY
```
* **Смысл словами:** В ансамбль исторических 12-месячных доходностей добавляется доходность, завершившаяся в месяце `t+1`, которая на дату `t` ещё неизвестна.
* **Что делает аудит:** `audit_information_set` проверяет `actual_scenarios == tuple(range(HORIZON, origin_index + 1))`. Поскольку `actual_scenarios` заканчивается на `origin_index + 1`, аудит обязан поймать утечку на первой же дате `1937-12` с сообщением `scenario lookahead or omission`.

### L2. Ансамбль видит незавершённые окна
* **Целевая строка в `Z28/run.py`** (строки 642–644):
```python
        scenario_points = tuple(
            annual[HORIZON:i + 1]
        )  # MUTATE_FUTURE_BOUNDARY
```
* **Замена:**
```python
        scenario_points = tuple(
            annual[HORIZON:i + HORIZON]
        )  # MUTATE_FUTURE_BOUNDARY
```
* **Смысл словами:** В ансамбль включаются все незавершённые 12-месячные окна, оканчивающиеся в месяцах `t+1 … t+11`, которые частично перекрывают горизонт прогноза.
* **Что делает аудит:** Аудит обязан поймать утечку на первой же дате с сообщением `scenario lookahead or omission`.

### L3. Опорная волатильность — средняя по всей выборке
* **Целевой блок в `Z28/run.py`** (строки 673–676):
```python
        reference_total = 0.0
        for point in reference_timed:
            reference_total += point.value
        reference_vol = reference_total / len(reference_timed)
```
* **Замена:**
```python
        reference_vol = statistics.fmean(
            p.value for p in rolling_vol if p is not None
        )
```
* **Смысл словами:** Вместо расширяющегося исторического среднего опорной волатильности `rolling_vol[HORIZON:i + 1]` в знаменатель масштаба подставляется безусловное среднее волатильности по всей истории ряда, посчитанное один раз.
* **Что делает аудит:** Аудит проверяет метки объекта `reference_timed`. Поскольку сам объект входов не меняется, аудит **не ловит** утечку (слепая зона аудита меток).

### L4. Центр ансамбля — средняя 12-месячная доходность по всей выборке
* **Целевой блок в `Z28/run.py`** (строки 681–682):
```python
        center, price_ensemble = centered_scale(ensemble, scale)
        baseline_score = crps_empirical(ensemble, outcome)
```
* **Замена:**
```python
        whole_center = statistics.fmean(
            p.value for p in annual if p is not None
        )
        center, price_ensemble = centered_scale(
            ensemble, scale, center=whole_center
        )
        leaked_base_ensemble = [
            x - statistics.fmean(ensemble) + whole_center for x in ensemble
        ]
        baseline_score = crps_empirical(leaked_base_ensemble, outcome)
```
* **Смысл словами:** Центр базового ансамбля сдвигается на безусловную среднюю годовую доходность за всю историю, и масштабирование для ценового прогноза производится вокруг этого константного центра.
* **Что делает аудит:** `audit_information_set` вызывается до вызова `centered_scale` и проверяет только исходные временные точки; значение центра в аудит не передаётся. Аудит **не ловит** утечку.

### L5. Недавняя волатильность — реализованная за месяцы t+1 … t+12
* **Целевая строка в `Z28/run.py`** (строка 651):
```python
        recent_vol_point = rolling_vol[i]
```
* **Замена:**
```python
        future_window = [
            log_returns[j] for j in range(i + 1, i + HORIZON + 1)
        ]
        recent_vol_point = TimedValue(
            value=(statistics.stdev(float(v) for v in future_window)
                   * math.sqrt(12.0) * 100.0),
            available_index=i + HORIZON,
            source_indices=tuple(range(i + 1, i + HORIZON + 1)),
        )
```
* **Смысл словами:** Вместо исторической волатильности за предшествующие 12 месяцев `t−11 … t` в числитель масштаба подставляется будущая реализованная волатильность за прогнозируемый период `t+1 … t+12`.
* **Что делает аудит:** Аудит проверяет `recent_vol_point.source_indices == tuple(range(origin_index - VOL_WINDOW + 1, origin_index + 1))`. Поскольку индексы источников лежат в будущем, аудит обязан поймать утечку с сообщением `recent-volatility source lookahead or omission`.

## 3. Два прогона на утечку и измеряемые величины

Для каждой из пяти утечек проводятся **два прогона**:
1. **Проверка аудита:** Аудит включён штатно. Если аудит поймал утечку, фиксируется статус `ПОЙМАН`, первая дата срабатывания и точный текст `AssertionError`. Если не поймал — фиксируется `НЕ ПОЙМАН`.
2. **Замер цены утечки:** Аудит заменяется пустой функцией-заглушкой (`audit_information_set = lambda **kw: {"passed": True}`). Расчёт доходит до конца, формируя полные ряды по всем датам.

### Измеряемые величины (на обоих маршрутах Yahoo и Shiller):

1. **Поддельный выигрыш над честным базовым:**
   По каждой дате $t$: штраф честного базового прогноза минус штраф прогноза с утечкой, где его строит исследователь:
   * для L1, L2, L4: $d_t = \mathrm{CRPS}_t(\text{честный базовый}) - \mathrm{CRPS}_t(\text{базовый с утечкой})$;
   * для L3, L5: $d_t = \mathrm{CRPS}_t(\text{честный базовый}) - \mathrm{CRPS}_t(\text{прогноз по цене с утечкой})$;
   * для L4 дополнительно рассчитывается выигрыш ценового прогноза с подглядывающим центром против честного базового.

   Для ряда $d_t$ рассчитываются:
   * средняя $\bar{d}$ и выборочное стандартное отклонение $s$;
   * параметр автокорреляционной зависимости $\tau$ и эффективное число наблюдений $n_{\mathrm{eff}} = n / \tau$ по правилу `dependence` из `Z28` (парный фильтр ACF с отсечением на неположительных суммах соседних лагов, максимум 24 лага);
   * честный 95 % доверительный интервал: $[\bar{d} - 1{,}96 \cdot s / \sqrt{n_{\mathrm{eff}}}, \bar{d} + 1{,}96 \cdot s / \sqrt{n_{\mathrm{eff}}}]$;
   * наивный 95 % доверительный интервал: $[\bar{d} - 1{,}96 \cdot s / \sqrt{n}, \bar{d} + 1{,}96 \cdot s / \sqrt{n}]$;
   * t-статистика честная: $t_{\mathrm{honest}} = \bar{d} / (s / \sqrt{n_{\mathrm{eff}}})$;
   * t-статистика наивная: $t_{\mathrm{naive}} = \bar{d} / (s / \sqrt{n})$;
   * вердикт по штатной функции `verdict` из `Z28` (`information_present`, `information_absent`, `not_established`).

2. **Прирост против честного выигрыша Z28:**
   По каждой дате $t$: разность между выигрышем с утечкой и честным выигрышем `Z28` ($\Delta_t = d_t - \delta_{t,\mathrm{Z28}}$).
   Рассчитываются: средняя, $s$, $\tau$, $n_{\mathrm{eff}}$ и честный 95 % доверительный интервал тем же прибором `dependence`.

3. **Изменение вердикта Z28:**
   Проверяется, меняет ли утечка вердикт `information_absent` на `information_present`.

## 7. Что заставит подозревать прибор, а не мир

1. **Утечка, ухудшающая штраф:** Если добавление будущей информации ухудшает CRPS ($\bar{d} < 0$), это свидетельствует о дефекте моделирования или нарушении динамической адаптации, а не об «ошибке в тесте». Например, в L3 замена скользящей адаптивной опорной волатильности на среднюю константу за всю историю подавляет способность масштаба подстраиваться под смену волатильностных эпох. Ухудшение штрафа публикуется как измеренный факт, без искусственной «подгонки» знака.
2. **Микроскопический выигрыш от малой утечки:** Если утечка на 1 месяц (L1) даёт выигрыш в сотые доли процентного пункта, честный доверительный интервал покажет неразличимость от нуля ($t_{\mathrm{honest}} < 1{,}96$), тогда как наивный интервал с $t_{\mathrm{naive}} > 2$ ложно заявит о статистической значимости. Это прямо иллюстрирует ловушку наивного доверия автокоррелированным рядам.

## 8. Разрешение прибора (выполнимость до расчёта)

В задаче Z29 нет гипотезы «подтвердилось/опровергнуто макро-утверждение». Выполнимость определяется **разрешающей способностью прибора**:
* Минимально различимый эффект (MDE) задаётся полушириной честного доверительного интервала:
  $$\mathrm{HW} = 1{,}96 \cdot \frac{s}{\sqrt{n_{\mathrm{eff}}}}.$$
* Если измеренный поддельный выигрыш $|\bar{d}| < \mathrm{HW}$, в отчёте он строго формулируется словами:
  *«Эффект утечки не различим данным прибором при $n_{\mathrm{eff}} = \dots$»*, с приведением фактического числа, а не фразой «утечки нет».

### 2026-09-25 · Р3: Переопределение эффекта базовых утечек (сдвиг сравнения Z28)

* **Что было.** В круге 1 для всех пяти утечек разница с честным прогоном рассчитывалась как вычитание честной дельты ($d - \delta$).
* **Что стало.** Для ценовых утечек (L3, L5) сохранено $d - \delta$. Для базовых утечек (L1, L2, L4) вычитание $\delta$ заменено на сдвиг сравнения Z28: $\delta - d = \mathrm{CRPS}(\text{baseline}_{\text{leaked}}) - \mathrm{CRPS}(\text{price})$. Вердикт Z28 при базовой утечке выносится по $\delta - d$; вердикт самого поддельного выигрыша $d$ сохраняется отдельной колонкой.
* **Причина.** Корректность сравнения: $\delta$ сравнивает цену с честным базовым, а $d$ — базовый с утечкой с честным базовым; при утечке в базовом исследователь наблюдает именно сдвиг $\delta - d$.
